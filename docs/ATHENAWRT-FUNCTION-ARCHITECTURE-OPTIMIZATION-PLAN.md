# AthenaWrt 全站功能架构、替代性与去留优化方案

> 版本基线：AthenaWrt 1.2.60-r2  
> 审查分支：`athenawrt/apk-fixed-signing`  
> 本方案性质：静态源码审查与优化建议，**不是实施记录**。本次不修改前端、后端、路由器配置或网络运行状态。  
> 保护红线：不改变 PPPoE、现网 VLAN（含 VLAN 2044）、IPv6 PD/SLAAC、防火墙/NAT、OpenClash、NSS/ECM 的既有配置和运行逻辑；不刷机、不重启、不执行网络切换。

## 1. 结论摘要

AthenaWrt 当前更接近一个“单页式设备控制台”，而不是多个独立 LuCI 页面：

- 菜单入口只有 AthenaWrt 管理台和一个跳转到原生 LuCI 的高级模式入口。
- 管理台内部有 8 个主要页面：概览、WiFi、设备、网络、存储、灯光、维护、高级。
- 主界面集中在一个约 291 KB、约 4,218 行的 `index.html` 中，页面结构、样式、交互和大量业务逻辑耦合在一起。
- Makefile 声明安装 24 个前端 RPC 脚本入口，并同时打包 Shell、ucode、legacy fallback、init 脚本及 FileBrowser Quantum 二进制。
- 原生 LuCI 已经存在，但当前部分功能又在 Athena 中重复实现；另有少量“界面入口存在、功能实际只是提示或本地状态变化”的历史代码。

**总体方向：保留 Athena 的硬件专属体验和高频只读仪表盘；把 OpenWrt 已成熟提供的通用系统管理能力交还原生 LuCI；把真正有价值的 Athena 专属功能做成小而可靠的模块；移除无后端、假数据、重复管理和高风险自动化。**

不建议把所有页面合并成一个更大的控制台，也不建议为了统一风格而重写现有网络逻辑。

## 2. 处理决策标准

每项功能按以下五类给出最终决策：

| 决策 | 含义 | 适用条件 |
|---|---|---|
| 保留 | Athena 继续作为主入口和实现者 | 硬件专属、体验明显更好、原生 LuCI 无等价能力 |
| 合并 | 保留能力，但合并入口、状态或重复操作 | 多个页面管理同一对象或重复展示相同状态 |
| 替代 | 改用原生 LuCI / 已有服务 / 标准工具 | 系统已有成熟等价实现，Athena 维护成本更高 |
| 移除 | 删除入口或功能 | 假功能、无实际价值、误导性展示、长期不可验证 |
| 重做 | 目标保留，但重做实现边界 | 功能有价值，但权限、可靠性、风险或数据来源不合格 |

判断优先级：真实可用性 > 安全性 > 系统兼容性 > 稳定性 > 操作效率 > 视觉效果。

## 3. 现有页面与功能去留评估

### 3.1 概览

**现有职责**
- 实时上下行速率、CPU、内存、运行时间、设备数。
- WAN / LAN 状态摘要。
- 网络拓扑示意、快捷操作、活跃应用识别。
- 跳转 WiFi、网络、设备等页面。

**建议**
- **保留**：实时上下行速率、CPU/内存、运行时间、在线设备、WAN/IPv6 摘要。这是 Athena 的核心价值，尤其是针对 Athena 硬件和 NSS/ECM 场景的状态聚合。
- **合并**：把重复出现在概览、设备页、高级页的服务状态和设备摘要统一数据源，避免每页独立维护一份状态。
- **重做**：拓扑区域明确标注“示意”或改为真实可验证的链路状态。当前页面标题含“示意”，不能包装成自动发现的物理拓扑。
- **可选/降级**：活跃应用识别。当前 `athena-apps.sh` 依赖 dnsmasq 查询日志、域名片段和 OAF 映射进行推断，不是 DPI，也不能可靠识别所有 App；DoH、共享 CDN、域名复用都会降低准确率。建议改名为“DNS 域名推测的活跃应用”，显示数据窗口与来源，默认可关闭；若准确率无法验收则移除。
- **保留**：2 秒采样的实时速率与中值滤波思路；不要退回慢速轮询，也不要将其宣传为测速结果。

**可替代性**：普通 CPU/内存/接口信息可由原生 LuCI 状态页替代；但统一的实时速率曲线、Athena 专属硬件信息和首页聚合不宜完全替代。

### 3.2 WiFi

**现有职责**
- 总开关、三频开关、SSID/密码、加密、信道、频宽。
- 访客网络。
- 恢复默认 WiFi。

**建议**
- **保留但收敛**：三频设备映射和面向普通用户的简单开关有 Athena 硬件适配价值。
- **替代/链接**：高级无线参数、复杂无线接口、漫游和驱动调试交给原生 LuCI「网络 → 无线」；不在 Athena 再造一套完整无线配置器。
- **重做**：访客网络只有在后端真正创建独立网络、隔离防火墙区、DHCP、无线接口，并验证隔离效果后才可作为正式功能。界面中“访客与内网隔离”不能只靠文字承诺。
- **移除**：任何只改前端状态、不调用 `athena-wireless.sh` 的旧版交互定义；保留最终实际生效的后端调用版本。
- **保留但增加强确认**：恢复默认 WiFi。操作前必须明确列出会改变的无线接口和凭据，生成随机密码并让用户保存；不得触碰有线网络。

**可替代性**：原生 LuCI 无线页可以完整替代通用配置；Athena 三频简化入口作为快捷层保留即可。访客隔离若由现有插件（例如 AdGuard Home）无法提供二层隔离，不应把 DNS 过滤当作替代品。

### 3.3 设备

**现有职责**
- 在线/离线设备列表、设备详情、备注、改名、识别新设备。
- 防蹭网/拉黑。
- 家长控制时间规则。

**建议**
- **保留**：统一设备清单、MAC/IP、在线状态、用户备注和已知设备标记。原生 DHCP 租约页通常不能提供同样的设备历史体验。
- **合并**：新设备提示与防蹭网入口合并为一个“待确认设备”状态，不单独制造第二套设备清单。
- **保留但重做规则生命周期**：MAC 拉黑和定时家长控制是 Athena 的附加价值，但需核对 nftables/fw4 规则唯一性、重启恢复、规则重复、IPv6 绕过、无线/有线一致性，以及与 OpenClash、防火墙 reload 的交互。
- **替代部分能力**：若用户只需要简单的 DHCP 静态租约和基础访问控制，原生 LuCI DHCP/防火墙页面即可；复杂时间策略才保留 Athena 专属管理。
- **移除**：模拟新设备、写死的设备计数、样例设备记录；所有设备状态必须来自后端采集，失败时明确显示“数据暂不可用”，不能显示演示数据。

**可替代性**：原生 LuCI 可替代基础租约管理；不能直接替代设备备注、识别状态和 Athena 自定义时间规则。

### 3.4 网络

**现有职责**
- 主路由、旁路由、AP 等模式入口。
- PPPoE / DHCP / 静态参数。
- 单臂配置分支、VLAN 子接口和网桥生成。
- 网口状态、网络诊断、ping、测速。

**建议**
- **最高保护级别**：网络页面不能当作普通设置页随意重构。
- **保留但隔离**：Athena 专属单臂配置助手有设备和项目价值；应独立为“高级网络向导”，进入前展示变更清单、备份、影响端口、预计断网时间、回滚条件，并逐项校验。
- **替代**：普通 PPPoE、DHCP、静态地址、IPv6、DNS、接口和防火墙管理优先使用原生 LuCI。Athena 只展示摘要，不维护第二套通用网络编辑器。
- **移除/禁用默认入口**：不把“切换主路由/AP/旁路由”放在普通用户的一键操作层。模式切换属于高风险网络重构，不应与测速、诊断并列。
- **重做自动回退**：`athena-netcheck` 当前在单臂模式下等待 45 秒，只依据 `br-lan` 是否存在管理 IP 判断健康，失败时调用模式脚本回退主路由并重启 network。单一 IP 条件不足以证明网络损坏，自动改写网络可能覆盖合法的自定义拓扑。建议先改为只读告警和保存诊断快照；自动回退必须做成显式启用、可取消、有完整回滚验证的保护机制。
- **谨慎保留**：`athena-vlan-pre` 在 network 启动前预创建 wan.X VLAN 子接口，可能是特定 DSA/NSS 单臂冷启动所需。必须以当前 Athena 真机启动日志验证，不能因代码“看起来多余”就移除。
- **保留**：只读网络诊断和测速，但明确测速服务器、失败原因、结果单位和测试时间；不要把 ping 连通性等同于互联网正常。

**可替代性**：通用网络配置几乎都能由原生 LuCI 替代；单臂 VLAN 向导和 Athena 冷启动适配属于专用能力，不应简单删除，但要与日常设置隔离。

### 3.5 存储与文件共享

**现有职责**
- 磁盘和分区信息、挂载、卸载、格式化。
- FileBrowser Quantum，限定 `/mnt/usb`，绑定 LAN 地址，随机密码。

**建议**
- **保留只读磁盘识别**：展示真实容量、分区、文件系统、挂载点和可用空间。
- **重做格式化入口**：后端已限制真实 USB 分区、分区设备、未挂载状态，并检查系统分区；前端目前从首个外置盘选择分区，需处理多 USB 盘、设备拔插竞争、挂载状态变化和格式化前再次确认。建议默认隐藏格式化，放在高级操作，要求二次输入目标分区名确认。
- **保留文件共享作为可选扩展**：当前 FileBrowser 服务仅在 USB 分区挂载到 `/mnt/usb` 且 LAN 地址可用时启动，监听 LAN IP，随机生成密码并以受限权限保存；共享根目录限制为 `/mnt/usb`。这部分符合项目既定安全目标。
- **建议拆包**：FileBrowser Quantum 二进制约 26.5 MB，当前被主 Athena APK 一并安装。若不是所有用户都需要 USB 文件共享，应拆为独立可选 APK/子包，主管理台不必承担所有用户都用不到的二进制体积和维护成本。
- **不建议默认换成 Samba/NAS**：文件浏览和家庭文件共享并不等于完整 NAS。只有用户明确需要 Windows 网络盘/SMB 时再评估 ksmbd/Samba，不能为了“替代”而增加常驻服务。
- **改进凭据展示**：当前服务脚本可通过 RPC 读取初始随机密码并在页面显示。应明确“初始密码”与用户后续修改密码的区别；建议只允许管理员主动查看、提供重新生成/轮换流程，并确保不写入普通日志。

**可替代性**：基础挂载可用原生 LuCI/Fstab；网页文件管理没有完全等价的 OpenWrt 原生功能。FileBrowser 可选拆包，不建议强行换成 NAS。

### 3.6 灯光与点阵屏

**现有职责**
- 点阵屏启停、亮度、显示项目、夜间模式、预览。
- 三色状态灯/绿色呼吸灯。

**建议**
- **保留**：这是 Athena 硬件专属能力，原生 LuCI 无等价替代。
- **合并**：点阵屏与状态灯归入“设备外观与指示灯”，但内部仍区分独立硬件驱动。
- **重做**：预览必须标明“模拟预览”，不能让预览数据看起来像设备实际输出。
- **移除或实现**：“打开完整管理”当前代码只弹出“尚未集成”的提示，应移除该按钮或真正实现页面；不要保留一个看似可用的功能入口。
- **验收**：每个开关必须回读真实状态，后端写入失败时恢复 UI 原状态；核实驱动不存在时显示“不支持”，不能只改变前端开关。

**可替代性**：无；保留。

### 3.7 维护

**现有职责**
- 重启、定时重启、固件升级、恢复出厂。
- 配置备份、恢复、自动备份和列表。

**建议**
- **替代基础系统操作**：普通重启、固件升级、恢复出厂、配置备份/恢复，优先调用原生 LuCI System/Flash Operations。原生流程与 OpenWrt sysupgrade 体系一致，避免 Athena 维护第二套固件升级 UI。
- **保留可选增强**：定时重启和自动备份属于便利功能，但需明确默认关闭、计划时间、保留数量、失败通知与恢复路径。
- **重做固件升级安全链**：当前脚本自己做上传、SHA256、sysupgrade -T、tar 结构/机型检查，再调用 sysupgrade。应避免把自定义 tar 头检查作为唯一安全边界；最终必须使用设备平台认可的 sysupgrade 校验和目标兼容性检查。
- **移除重复入口**：若使用原生 LuCI 完成升级/恢复，Athena 只保留状态与快捷跳转，不再复制一套上传/刷写界面。
- **特别提示**：恢复出厂和 sysupgrade 仍是高风险动作，方案阶段不测试、不执行。

**可替代性**：很高。原生 LuCI 可以替代绝大部分维护操作；Athena 可保留定时计划、备份策略摘要和跳转入口。

### 3.8 高级

**现有职责**
- CPU/内存资源、进程操作。
- 第三方服务启停、服务详情。
- APK 软件包管理。
- 系统日志。
- 管理密码、默认界面、主题、速率单位、KPI 排序、UI 缩放。

**建议**
- **资源占用保留只读摘要**：CPU/内存和关键服务状态适合放在概览或高级诊断。
- **替代进程管理**：进程终止/重启优先交给原生 LuCI Processes；Athena 不应鼓励用户停止任意进程。现有脚本虽有 PID 身份复核和关键进程保护，仍应减少暴露面。
- **替代通用服务启停**：原生 LuCI System → Startup 是服务启停的权威入口。Athena 可显示 OpenClash、AdGuard Home、FileBrowser 等关键服务状态，并提供“打开原生管理页”，不再重复做通用 init 管理器。
- **重做服务清单**：只展示真实安装、真实运行且有对应 init/service 的服务。当前页面存在 AdGuard Home、OpenClash、FileBrowser、DDNS、WebDAV 等固定展示内容的痕迹，必须核对是否动态取数，禁止把示例服务写死为“运行中”。
- **替代通用软件包管理**：优先原生 LuCI Software/APK 管理。Athena 仅保留关键包保护清单和升级风险提示；任何自定义包操作必须保护 OpenClash、NSS/ECM、内核、网络栈、LuCI 和依赖组件。
- **替代系统日志查看**：原生 LuCI System Log / Kernel Log 是基础日志入口。Athena 可保留精选告警摘要和导出，不必维护第二套完整日志查看器。
- **保留 Athena 专属偏好**：主题、单位、KPI 排序、UI 缩放、默认界面。
- **替代 SSH 开关**：源码中最终的 `toggleSsh` 实际提示“SSH 服务由系统安全策略管理，始终启用”，没有真正开关；应移除开关式入口，改成状态说明和原生 LuCI 跳转。
- **密码修改**：原生 LuCI System → Administration 可承担 root 密码修改。若保留 Athena 快捷入口，必须避免同时维护两套密码状态和重复脚本。

**可替代性**：服务、软件包、日志、进程、密码管理均有较强原生替代能力；主题和 Athena 仪表盘偏好没有必要替代。

## 4. 明确发现的“无必要/假功能/重复实现”候选

以下是源码层面已能确认或应优先核实的项目：

| 项目 | 源码证据/现象 | 建议处理 |
|---|---|---|
| SSH 开关 | 最终定义只显示“SSH 始终启用”的提示，不执行启停 | 移除开关 UI，改为只读状态 |
| 点阵屏完整管理按钮 | 最终函数只提示页面尚未集成 | 移除按钮或实现完整页面 |
| 网络拓扑 | 页面文案明确标注“示意” | 改名为示意图或移除，不得声称实时物理拓扑 |
| 活跃应用识别 | DNS 查询日志 + 域名片段规则推测 | 可选功能、标注推测性质；准确率不合格则移除 |
| 预览稿残留函数 | 同一 HTML 内多处函数重复定义，早期有只改 UI 的占位实现，后续定义覆盖 | 清理死代码和重复定义，保留唯一最终实现 |
| 设备/状态样例 | 页面初始 HTML 存在示例数据和静态文案 | 所有动态卡片统一由后端渲染；加载失败显示错误/过期状态 |
| 高级服务管理 | 与原生 LuCI Startup 和插件自带管理页面重叠 | 收敛为关键服务状态 + 原生页面入口 |
| 软件包管理 | 与系统原生 APK/LuCI 软件管理重复 | 原生管理为主，Athena 只负责关键包保护和风险提示 |
| 固件升级/恢复 | 与原生 LuCI Flash Operations 重复 | 原生流程为主，Athena 不维护第二套刷写 UI |

注意：重复定义不等于最终用户一定能触发假功能；需要在清理时保留最终生效的实现并做回归测试，不能简单删除所有早期定义而不检查依赖。

## 5. 后端与安全边界：优先级高于视觉重构

### P0：权限面收敛

当前 ACL 对 `luci-app-athena` 授予多组 UCI 写权限（包括 `network`、`wireless`、`dhcp`、`system`、`ddns`、`ttyd`），并允许对多个 libexec 脚本执行、对文件 RPC 的 `exec/write/read` 操作；还包含 `/etc/init.d/network` 执行权限及临时上传文件读写权限。

建议：
1. 逐个 RPC 建立“动作—参数—权限—影响对象”清单。
2. 把只读 RPC 与写操作分开。
3. 删除不再使用的 ACL 授权和旧脚本授权。
4. 不允许前端传任意命令、路径、服务名或 UCI 键；后端使用固定白名单和严格参数校验。
5. 对网络变更、格式化、恢复、刷写、重启等动作单独授权并二次确认。
6. 不把“页面隐藏按钮”当作安全措施，必须由后端拒绝越权参数。

### P0：网络保护

- `athena-mode.sh` 会写入 network UCI、重建 VLAN/bridge，并存在停止/启动 qca-nss-ecm 的流程。任何优化必须先做静态差异审查和独立测试，不能在当前运行路由器上直接试错。
- `athena-netcheck` 有自动回退并重启 network 的行为，必须优先重新评估。
- `athena-vlan-pre` 可能是单臂冷启动依赖，应保留为待验证项，不可直接删。
- 网络模式配置与普通只读诊断应彻底分离。

### P1：状态真实性和错误呈现

多个前端数据加载函数使用空 catch，可能导致 RPC 失败时不提示错误，页面保留旧数据或默认值。建议统一状态模型：
- 正常：显示当前值和更新时间。
- 加载中：显示明确加载状态。
- 失败：显示错误原因和重试入口。
- 过期：标注“最后成功更新时间”，不能继续显示成实时值。
- 不支持：明确标记设备/驱动不支持。

### P1：功能唯一数据源

状态、无线、设备、磁盘、服务、灯光、备份等模块应明确唯一后端数据源。Shell/ucode/legacy fallback 可以保留必要兼容，但必须有测试覆盖，不能出现多个实现逐渐偏离。

## 6. 建议的新功能分类与菜单结构

不增加顶层菜单数量，先重组现有 8 个入口：

1. **总览**
   - 实时网速、CPU/内存、运行时间、WAN/IPv6、设备数量
   - 关键服务告警
   - 可选 DNS 应用推测（默认关闭或折叠）

2. **无线**
   - 三频状态和常用配置
   - 访客网络（通过隔离验收后开放）
   - 高级无线设置 → 原生 LuCI

3. **设备**
   - 在线设备、已知设备、新设备
   - 设备备注和拉黑
   - 家长控制（作为高级子功能）

4. **网络**
   - WAN/PPPoE、IPv4/IPv6、接口状态只读摘要
   - 诊断、ping、测速
   - 单臂/VLAN 专家向导（单独入口、强确认）
   - 完整网络配置 → 原生 LuCI

5. **存储**
   - USB 磁盘和挂载状态
   - 文件共享（可选组件）
   - 格式化（默认折叠到高级危险操作）

6. **设备灯光**
   - 点阵屏
   - 状态灯
   - 真实状态与模拟预览明确区分

7. **维护**
   - 系统信息
   - 定时重启、自动备份策略
   - 原生 LuCI：重启/升级/恢复/备份
   - 危险操作独立确认

8. **高级与诊断**
   - 资源和关键服务只读状态
   - OpenClash / AdGuard Home 等插件原生管理入口
   - 日志摘要
   - Athena 外观和偏好
   - 软件包、服务、进程完整管理 → 原生 LuCI

## 7. 实施顺序与验收门槛

### 阶段 A：静态清理与完整映射（不改行为）
- 建立菜单、页面、按钮、参数、RPC、后端脚本、UCI/文件/服务依赖矩阵。
- 标出重复定义、死代码、样例数据、空 catch、未使用脚本。
- 每个控件标记：只读 / 真正写入 / 仅本地偏好 / 占位 / 危险操作。
- 产出完整《全站功能与调用链清单》。

验收：每个可点击控件都能说明它调用哪个后端动作，或明确标注为本地纯 UI 操作。

### 阶段 B：功能去留确认（不改运行配置）
- 按“保留、合并、替代、移除、重做”逐项列出建议。
- 由用户确认去留，尤其是访客网络、家长控制、活跃应用、FileBrowser、自动回退、进程管理。
- 确认原生 LuCI 对应页面路径及当前系统是否安装。

验收：没有未经用户确认的功能删除或替换。

### 阶段 C：低风险实现优化
- 清理重复 JS 定义和预览稿残留。
- 统一状态加载、错误、过期标识。
- 合并重复状态组件。
- 去掉无效 SSH 开关和未集成按钮。
- 不改网络配置生成逻辑。

验收：静态检查、浏览器页面回归、RPC 参数白名单测试通过。

### 阶段 D：权限和高风险功能整改
- 缩小 rpcd ACL。
- 评估网络自动回退和模式切换。
- 对格式化、备份恢复、升级、重启增加强保护。
- FileBrowser 独立可选拆包评估。

验收：每个危险操作有后端校验、二次确认、失败反馈和可恢复策略；网络相关变更在独立测试环境完成，不在当前在线路由器上试错。

### 阶段 E：视觉与交互优化
只有功能架构和调用链稳定后，才做 CSS、响应式和视觉调整。

## 8. 当前不应做的事情

- 不应立即重写 291 KB 单页 HTML。
- 不应为了菜单统一而删除单臂 VLAN 专用能力。
- 不应把 NSS/ECM 开关伪装成可配置项；当前硬件分支应以实际运行状态为准。
- 不应在 Athena 页面重复提供一套完整的 OpenClash 管理器。
- 不应把 DNS 域名推测称为精确 DPI。
- 不应直接移除 `athena-vlan-pre` 或修改 `athena-mode.sh`。
- 不应在当前设备上测试自动网络回退、模式切换、sysupgrade、恢复出厂、格式化。
- 不应把功能“看起来有按钮”视为已实现，也不应把构建成功视为运行功能已验收。

## 9. 本次审查的证据边界

本方案基于 GitHub 当前分支中以下源码静态检查：
- LuCI 菜单定义、rpcd ACL。
- `index.html` 页面结构、函数定义和 RPC 调用。
- Makefile 安装清单。
- 状态、网络模式、单臂、设备、服务、资源、诊断、密码、软件包、备份、恢复、磁盘、主题、点阵屏、无线、测速、LED、UI、家长控制、应用识别等后端脚本。
- FileBrowser init、Athena 启动/网络自检/VLAN 预创建 init 脚本。

**未在本次执行：** 真机逐按钮测试、网络配置写入、服务启停、格式化、刷写、恢复出厂、浏览器自动化、OpenClash/NSS/ECM 运行状态变更。因此文中涉及运行时准确率、隔离效果、规则恢复和插件状态的项目均列为后续验收项，不伪称已通过。

# AthenaWrt 功能架构与优化执行原则

> 实时进度、提交、构建和设备验收只维护在 `ATHENAWRT-PROJECT-STATUS.md`。本文件只保留长期决策原则。
> 更新日期：2026-11-03

## 1. 目标

在不破坏现有网络、硬件加速和用户功能的前提下，修复 Athena 的安全与状态真实性问题，优化 Athena 自有页面，并维持独立 APK 交付。

## 2. 必须保持的边界

- 不改变 PPPoE、VLAN 2044、IPv6 PD/SLAAC、防火墙/NAT、OpenClash、NSS/ECM 驱动及硬件加速现网状态。
- 不在在线设备试错固件刷写、恢复出厂、网络模式切换、重启网络或磁盘格式化。
- **任何原生 LuCI 页面、菜单、ACL、软件包管理器及后端均不属于 Athena 修改范围。**
- 不刷写整机固件；继续使用 GitHub Actions 构建独立 APK并通过签名、哈希验证。

## 3. 功能决策原则

- 保留：硬件状态仪表盘、三频快捷操作、单臂/VLAN 专用能力、设备识别、LED/点阵屏和必要存储能力。
- 原生替代：通用系统管理能力可以从 Athena 跳转原生 LuCI，但不得为了实现 Athena 安全限制而修改原生组件。
- 重做：仅对有证据的安全、事务、状态真实性或错误处理缺陷进行修改。
- 移除：只有确认无调用者、无兼容依赖后才移除。
- 不增加 NSS/ECM 前端开关；不把 DNS/OAF 推测为 DPI；不把静态拓扑或动画冒充实时数据。

## 4. 安全整改重点

1. Athena ACL 只保留实际调用链所需权限。
2. 固件升级后端在 flash 阶段重新核验路径、目标机型、归档结构、哈希与 sysupgrade 平台验证。
3. 恢复出厂、服务启停和网络模式的危险分支必须由后端约束，不依赖前端隐藏按钮。
4. Athena 包管理对关键组件做直接保护及依赖事务预演；不修改原生 package-manager。
5. 备份恢复、USB 设备身份、nftables 规则所有权与多 UCI 事务仍按 P1 继续专项审计。

## 5. Athena 页面设计原则

- 标准 Liquid Glass；均衡密度、清晰层级、克制动效。
- 默认跟随系统明暗主题，允许用户手动浅色/深色覆盖，并持久化所选模式。
- 桌面/平板有效利用多列布局；手机保持单列、完整文字和可触控控件。
- 实时数值必须来自真实 RPC；无数据或读取失败时显示未知/读取中，不以示例数据伪装。
- 保留 Athena 既有功能分工，不为普通体验优化而重写整套 SPA 或修改原生 LuCI。
- 通过静态语法、调用链、mock/CI 和签名/哈希验证；危险设备操作不做真机试错。

## 6. 实施流程

用户要求相关工作一次完成时，将同一范围的 Athena 源码修改合并为完整批次；完成全部修改后再统一验证和构建。若用户没有要求拆分，不逐项请求操作确认。


## 7. 网络配置变更：复用原生 UCI 回滚

- 不另造 Athena watchdog、pending 守护进程、第二套 token 或自定义回滚框架；复用目标 ImmortalWrt/LuCI 自带的 UCI apply-with-rollback 能力。
- 预期流程：Athena 将本次网络修改暂存到当前 LuCI RPC 会话的 UCI transaction，再调用原生 `/admin/uci/apply_rollback`。原生后端生成确认 token 并启动回滚倒计时；用户管理端重新连通后走原生 `/admin/uci/confirm` 确认，超时未确认则由原生机制回滚。
- 当前 `athena-mode.sh` 使用命令行 UCI 修改和 `uci commit` 的路径不能直接视为 LuCI session staged changes。必须先完成调用链改造与会话绑定验证；禁止先 commit 再调用 apply_rollback，造成回滚事务没有捕获原始配置。
- 覆盖 router/AP/single/bypass 所有可能改变管理链路的操作；保留现有单臂本机 IP/VLAN 检查作为补充检查的可能性，但不把它当成客户端失联检测，不新增重复 watchdog。
- 仅修改 Athena 自有脚本、RPC 接入及前端提示，不修改原生 LuCI 页面、菜单、ACL 或后端。前端只清楚说明短暂断网及原生回滚保护，避免增加 SSH 手动恢复步骤。
- 实施前核对目标设备的 LuCI 版本、原生回滚 endpoint、RPC session、UCI staged changes 与现有 Athena RPC 封装；确保只应用本次 Athena 变更，不提交用户在其他 LuCI 页面中未应用的配置。离线/CI 验证完成后再安排带外救援条件下的设备验收。

## 8. 存储中心与 KSMBD 按需 NAS

- 存储中心采用一个入口、三个独立模块：**磁盘与卷管理**、**网页文件管理（FileBrowser）**、**NAS 网络共享**。NAS 未安装时显示“安装 NAS”；安装成功后以真实后端状态动态显示 NAS 管理区域。
- NAS 第一阶段采用 KSMBD + SMB，不默认安装 NFS。只有确认存在 NFS 客户端需求，且目标固件软件源/内核模块满足要求时再扩展。
- 一键安装是完整后端事务，不只是前端按钮：检查软件源签名、架构、运行内核 ABI、磁盘空间、端口和依赖；先做 APK transaction simulate；任何事务会改变 OpenClash、NSS/ECM、内核、网络栈或关键系统包时拒绝安装。由目标固件的已配置签名软件源解析依赖，不猜测内核包版本。
- 新增独立 `athena-nas.sh` 管理 NAS 软件包所有权、服务状态、共享、账户、权限与生命周期；`athena-disk.sh` 只管理块设备和卷。Makefile 安装清单、RPC ACL、后端 allowlist、前端入口和动态 NAS 页面要成套实现。
- 安装后初始化 LAN-only SMB 服务，默认禁用 guest/匿名访问；安全生成访问凭据；共享路径只允许落在已登记且真实挂载的数据卷内，默认兼容 `/mnt/usb`。不共享系统目录、overlay、未挂载目录，不开放 WAN。
- 页面提供真实安装/运行状态、共享信息、访问地址、凭据管理和启停/卸载入口。安装完成自动刷新显示 NAS 模块；安装失败显示后端真实错误，不伪报成功。
- “停止”只停止服务并禁用自启，保留软件包、配置、账户和数据；“卸载”才移除 Athena 拥有的 NAS 软件及集成。卸载必须检查依赖关系和软件包所有权，不删除磁盘文件、不格式化分区、不卸载其他软件正在使用的共享依赖；必要时备份用户配置。
- FileBrowser 继续使用 `/mnt/usb`，不改变现有 USB 分区校验/格式化安全约束。卸载卷前先停止 NAS/FileBrowser 消费者并检查 busy；热拔出时停止依赖服务。后续再逐步以 UUID/LABEL 识别卷，避免设备节点变化挂错盘。
- NAS 属当前 r4 之后的独立批次；未经用户明确授权不在设备上安装/卸载软件包。交付前必须验证软件源、APK 事务、内核 ABI、包依赖、ACL、路径隔离、停止/卸载边界及动态页面状态。

## 9. r5：可靠性、安全性与前后端闭环

### 9.1 凭据策略
- 主 WiFi 执行“恢复默认”时，三个主频段统一恢复为用户指定的默认密码 `12345678`；后端设置并回传真实结果，前端读取返回值并提供复制。确认弹窗明确说明该密码是公开默认值，建议随后修改，不得宣称为随机强密码。
- 此固定默认值只作用于主 WiFi 恢复默认流程。访客 WiFi 不继承该密码；访客凭据由用户设置或独立随机生成。
- FileBrowser 按当前初始化脚本真实配置工作：用户名 `admin`、随机密码 `/etc/filebrowser.password`（0600）。前端通过现有受限 RPC 读取实际凭据和服务状态，默认遮罩、主动查看、可复制，不得显示虚构的 root/admin 或路由器密码。

### 9.2 存储与备份恢复
- eMMC 格式化入口从 Athena 页面移除；格式化按钮仅对后端确认的真实 USB 分区开放。后端 USB 身份、挂载、swap、系统分区检查不能被前端替代。
- 备份上传恢复增加独占锁、请求/文件绑定、权限受限临时目录、大小上限、失败清理和归档成员验证；拒绝绝对路径、目录穿越、链接和特殊文件。验证兼容真实 sysupgrade 备份，不自行扩大恢复范围。
- NAS/FileBrowser 是数据卷消费者。卸载卷前停止消费者并检查 busy；不得因为关闭/卸载 NAS 删除或格式化数据。

### 9.3 防火墙与家长控制
- 设备拉黑功能统一使用 fw4/nftables Athena 专属规则对象；不再同时写 nftables 与 iptables，不得按 MAC 全局搜索删除规则。
- 规则恢复必须幂等，删除动作限定 Athena 自己的规则。
- 家长控制规则先在临时文件生成和校验，再原子替换；参数、跨午夜星期偏移和 nft 语法验证通过后才 reload firewall。失败时保留上一个有效规则集。
- 访客 WiFi 修改涉及 wireless/network/dhcp/firewall 多配置，增加本次事务备份、冲突检查、统一应用与失败回滚，不能留下半套配置。

### 9.4 进程、服务与包管理
- 进程结束先 TERM，等待并重新核验 PID/starttime/comm；仅当进程仍存在且身份一致时才允许 KILL 兜底。
- 动态发现服务只读；启停必须走固定 allowlist。通用服务、日志、密码、进程、软件包、固件刷写优先跳转原生 LuCI，不重复造通用系统管理器。
- 关键包保护继续在 Athena 后端执行；用设备真实 APK-tools 3.0.5 输出验证 `--simulate` 事务解析，不能因为前端隐藏入口就认为已安全。
- 软件源索引刷新按钮准确命名，不冒充软件包升级。

### 9.5 全站交互状态统一
- 所有只读数据采用 loading/live/stale/error/unsupported 五态，并显示最后更新时间；失败后不得保留静态演示数据冒充真实数据。
- 所有写操作采用明确的 pending/success/failure 状态；禁止先乐观改 UI、后端失败仍显示成功；禁用重复提交并显示后端具体原因。
- 移除假控件和假反馈，包括 SSH 假开关、无后端的 PPPoE 密码编辑、日志导出/清空假操作，以及被误认为实时拓扑的固定示意数据。
- 清理重复函数/旧代码前先搜索整个仓库的外部调用者，不随意删除兼容入口。

## 10. 后续批次边界

- r4 只完成已经提交的安全整改和 Liquid Glass 页面批次；r4 构建和设备验收独立进行，本节不追改当前 r4。
- r5 优先完成本文件第 9 节中的凭据、存储、备份、nftables、家长控制、访客网络事务、进程操作、统一状态模型和原生 UCI 回滚接入。
- r6 再实现 KSMBD 按需 NAS；安装、停止/启用、卸载为不同生命周期操作，卸载不得删除数据或移除其他软件正在使用的依赖。
- 所有修改仍限定在 Athena 自有前端与后端；不修改原生 LuCI 页面、菜单、ACL、软件包管理器及后端，不改变 PPPoE、VLAN 2044、IPv6、防火墙/NAT、OpenClash、NSS/ECM 和硬件加速现网配置。
- 未经用户授权，不在设备执行网络切换、重启网络、格式化、固件刷写、恢复出厂、NAS 安装/卸载或其他高风险操作。

# AthenaWrt 功能架构与优化执行原则（精简版）

> 本文件只定义决策原则和实施顺序。项目实时状态、构建/验收信息只维护在 `ATHENAWRT-PROJECT-STATUS.md`；详细源码证据按需查阅两份审计文档，不在此重复记录。
> 更新日期：2026-11-03

## 1. 总目标

在不破坏现有网络、硬件加速和用户功能的前提下，收敛 AthenaWrt 与原生 LuCI 的重复能力，修复真实安全/正确性问题，降低维护复杂度。

## 2. 必须保持的设备边界

未经用户明确授权，不修改：
- PPPoE、VLAN 2044、IPv6 PD/SLAAC、防火墙/NAT。
- OpenClash、NSS/ECM、相关驱动及硬件加速状态。
- 固件刷写、恢复出厂、网络模式切换、磁盘格式化等高风险操作。

不刷整机固件；继续使用独立 APK 和 GitHub Actions。不得以隐藏按钮代替后端安全校验。

## 3. 功能决策规则

每项功能只允许归入以下一种处理方式：
- **保留**：Athena 硬件专属或确有显著使用价值。
- **合并**：多个入口实际操作同一资源/状态源。
- **原生替代**：通用系统管理优先跳转原生 LuCI，不维护第二套实现。
- **移除**：确认无真实行为、无调用者且无启动/兼容依赖后才删除。
- **重做**：存在安全、状态真实性、事务或错误处理问题。

优先复用原生 LuCI：接口/网络基础配置、DHCP/DNS、防火墙、无线高级参数、系统日志、进程/服务、root 密码、软件包管理、固件维护。保留 Athena 的硬件状态仪表盘、三频快捷操作、单臂/VLAN 专用能力、设备识别、LED/点阵屏及必要的存储专用功能。

不得仅因页面入口相似就合并 LED 与点阵屏；不得增加 NSS/ECM 用户开关；不得把 DNS/OAF 推测描述为 DPI；不得把静态拓扑或动画数据描述为实时状态。

## 4. 整改优先级

### P0：安全边界
1. rpcd ACL 最小权限：追踪所有调用者后，移除未使用的通用执行/写权限。
2. 固件升级：flash 后端独立执行镜像结构、机型和路径校验。
3. 危险操作：网络模式、恢复出厂、备份恢复、格式化等采用后端确认/互斥保护；前端弹窗不是安全边界。
4. 包管理：Athena 后端保护 OpenClash、NSS/ECM、内核、网络栈和关键 LuCI；明确原生包管理入口的权限边界。

### P1：数据与事务正确性
1. 访客网络多配置写入具备冲突检测、备份和失败恢复。
2. nftables 规则限定 Athena 自有 chain/set，更新原子化、可持久恢复。
3. USB 格式化在执行前再次核验真实设备身份、挂载和系统盘关系。
4. FileBrowser 随机密码、LAN-only 绑定、固定 /mnt/usb 根目录；USB 未挂载时不启动。
5. 状态采集失败明确显示错误/过期，不用静态样例冒充实时数据；首页速率必须使用真实采集 RPC。
6. 进程管理 TERM→身份复核→必要时 KILL；错误返回必须传到 UI。

### P2：维护成本与体验
1. 删除无调用者的重复/预览代码前，先做全仓库调用者与启动依赖检查。
2. 通用系统管理收敛为原生 LuCI 入口。
3. 保留八个主要页面的清晰分工，不做无必要的 SPA 大重写或 CSS 重构。
4. Makefile、ACL、安装文件、工作流触发路径和测试清单保持一致。

## 5. 精简实施流程

**步骤 1：只查未决高风险项。** 不重复盘点已经确认的普通控件；对证据充分的问题直接给出结论，缺少设备运行证据的标为待验收。

**步骤 2：输出单一整改清单。** 每项记录：证据、风险、建议改法、影响范围、是否需要真机测试。分类为“必须修 / 建议修 / 保留不动”。

**步骤 3：用户确认范围。** 未确认不删除功能、不替代菜单、不改网络相关后端。

**步骤 4：分批实施。** 每批仅处理一个逻辑领域；先静态检查和 mock/自动化测试，再提交 GitHub。纯文档更新不触发 APK 构建。

**步骤 5：按风险验收。** 只有影响 APK 的源码变更才构建新 APK；高风险网络/刷写/恢复/格式化不得在当前在线设备上试错。安装前验签、模拟升级，用户明确同意后才正式安装。

## 6. 当前阶段

当前阶段和下一项任务以 `docs/ATHENAWRT-PROJECT-STATUS.md` 为准。当前重点为 P0 权限/危险操作边界与 P1 事务正确性收敛；暂不做 CSS、SPA 重写或未经确认的功能删改。

# AthenaWrt 最终功能去留矩阵（C2-E）

> 日期：2026-11-02
> 基准：C1 全站功能重组、C2 全站操作清单、C2-D 原生 LuCI 能力核对
> 状态：功能范围决策基线；代码实施前仍需按批次验收
> 原则：不因“原生可能有”就删除 Athena 功能，不因“前端有按钮”就默认保留无效入口。

## 1. 最终决策标签

- **保留**：Athena 的产品核心或设备专属能力。
- **优化**：功能保留，但修正表达、状态、交互或可靠性。
- **合并**：多个入口/模块归并到同一页面分组。
- **原生跳转**：通用系统能力由 LuCI 负责，Athena 提供清晰入口；必须先在设备确认原生页面可用。
- **移除**：没有真实动作、重复且无独特价值的 UI 入口。移除 UI 前仍需全仓库调用者核查，不能顺手删除后端脚本。
- **暂缓**：依赖后端安全整改或设备端证据。

## 2. 八页最终去留

| 页面 | 保留 | 优化/合并 | 原生跳转候选 | 移除/暂缓 |
|---|---|---|---|---|

| 设备 | 设备列表、备注、改名、识别、拉黑、家长控制 | 在线状态规则、最近观测时间、规则摘要；拉黑/家长控制状态分离 | 无，属于 Athena 专属 | 规则写入整改前暂缓扩大操作 |

## 3. 全局功能决策

### 3.1 首页
- 首页主视觉固定为实时上下行速率，不再以 NSS/ECM 硬件加速作为首页核心。
- NSS/ECM 仅可显示只读状态，禁止新增开启/关闭按钮。
- CPU/内存/在线设备数作为次级指标。
- WAN/IPv6 状态单独显示，不能用一个“网络正常”标签掩盖细节。
- 静态拓扑图从首页主区域移除；不得用逻辑示意图推断设备在线。

### 3.2 原生 LuCI 与 Athena 的边界
- 原生 LuCI 是通用系统配置主入口；Athena 是设备专属快捷管理和单臂/VLAN 专项工具。
- 当前仓库配置只支持“原生能力存在于构建配置”的结论，不支持“当前设备所有菜单可用”的结论。
- 防火墙和软件包管理已有较明确构建证据；仍需设备菜单/ACL核对后再把 Athena 的重复入口改成跳转。
- 不删除 Athena 网络向导、三频 WiFi、设备识别、家长控制、USB 受限文件访问、LED/点阵屏和自动备份策略。

### 3.3 无效/误导入口
- SSH 假开关：移除 UI 控件或改只读状态说明；不得影响 sshd 服务。
- 点阵屏“打开完整管理”：无真实动作，移除该 UI 入口；不删除矩阵屏后端功能。
- 软件包页“检查更新”：若动作仅为 `apk update`，改成“刷新软件列表”，不触发升级。
- 活跃应用：标记为“域名线索推测”；不声称 DPI。
- 点阵屏预览：标记为“预览”，不声称设备实时画面。

## 4. 实施批次

### C3-A：第一批低风险页面整理
1. 首页信息层级调整：实时速度主视觉、真实状态、错误态。
2. 删除首页静态拓扑主卡，保留必要连接状态摘要。
3. 活跃应用标识“域名线索推测”。
4. 灯光页面删除无效“打开完整管理”入口（先全仓库核查调用者）。
5. 高级页面移除 SSH 假开关，改成只读说明（不操作服务）。
6. 软件包文案改为“刷新软件列表”。
7. 维护页只调整分组和说明，不改变任何备份/升级/恢复后端动作。
8. CSS 暂不大改；只允许必要的 DOM 结构调整，保持现有视觉体系。

### C3-B：依赖设备原生菜单核验
1. 通用网络配置入口跳转原生 LuCI。
2. 防火墙入口跳转原生 LuCI。
3. 软件包管理入口跳转原生 LuCI 或保留 Athena 包装层（必须保证关键包保护）。
4. 高级系统管理入口按设备实际菜单做跳转。

### C3-C：依赖后端安全整改
- 访客网络事务化。
- 设备拉黑/家长控制 nftables 所有权统一。
- 网络模式危险操作票据和保护配置 diff。
- 固件升级后端复验、恢复出厂确认票据、配置恢复并发保护。
- USB 格式化设备身份复核。
- 服务路径校验、进程 TERM/KILL 流程。

## 5. 保护约束

任何页面调整不得：
- 更改 PPPoE、VLAN 2044、IPv6 PD/SLAAC、LAN VLAN 和防火墙/NAT 现有配置。
- 关闭、重启或重载 OpenClash、NSS/ECM，或改变它们的运行逻辑。
- 增加 NSS/ECM 控制开关。
- 引入 NAS/Samba。
- 执行 sysupgrade、firstboot、网络模式切换、磁盘格式化或配置恢复。
- 在未核实原生页面和 ACL 前删除 Athena 通用管理入口。

## 6. 验收标准

- 每个显示中的开关均有真实后端动作或明确标记只读。
- 每个按钮都能对应具体 RPC、参数、返回值和错误反馈。
- 不存在“点击只 toast 提示未集成”的假入口。
- 数据卡片明确区分实时、缓存、推测、静态说明。
- 原生跳转目标在当前设备确实存在、可访问且权限正确。
- 移动端页面不产生全局横向溢出。
- APK 构建、验签、安装包哈希一致；设备端逐页验收。
- 网络关键配置只读对比，未授权不做网络切换测试。

## 7. C2 阶段结论

C1/C2/C2-D 已形成八页职责、逐控件调用清单和原生 LuCI 能力边界。本文将当前建议收敛为可执行的最终去留矩阵。

此矩阵确认的是功能范围，不等于代码已修改。第一批可以从 C3-A 低风险项目开始；原生菜单跳转与危险操作仍需相应证据和安全整改。
